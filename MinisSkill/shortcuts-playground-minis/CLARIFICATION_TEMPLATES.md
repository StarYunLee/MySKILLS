# Clarification Templates

## 作用

在需求存在关键歧义时，用最少问题确定实现边界，避免错误开工和后续返工。

## 适用条件

满足任一项即进入澄清：

- 输入方式不明确
- 输出目标不明确
- 写入方式不明确
- 执行顺序不明确
- 完成后行为不明确
- 是否接受外部依赖不明确

## 执行规则

- 每次只问会改变实现路线的问题
- 问题数量按关键歧义数量决定，不人为限制为固定 1~3 个
- 每个问题都使用固定选项式格式
- 提问后必须给出推荐流程
- 提问后必须给出可直接复制确认的文本
- 未澄清前不进入 XML 生成

## 固定输出格式

```text
我理解的流程：……

1. 问题1
• A：回答1
• B：回答2
• C：回答3

2. 问题2
• A：回答1
• B：回答2
• C：回答3

推荐流程：……
可直接复制确认：按推荐流程：1A、2B。
```

## 问题维度

### 1. 入口

```text
1. 这个快捷指令从哪里启动？
• A：手动运行
• B：从分享菜单接收内容后运行
• C：小组件、自动化或其他入口
```

### 2. 输入方式

```text
2. 主要输入方式是什么？
• A：弹出输入框手动输入
• B：读取剪贴板或当前已选内容
• C：接收 URL、图片、文件等外部输入
```

### 3. 目标对象

```text
3. 目标要写入或输出到哪里？
• A：系统原生应用
• B：第三方应用
• C：文件、URL 或分享面板
```

### 4. 写入方式

```text
4. 目标内容要怎么处理？
• A：新建一条或新建一个对象
• B：写入固定对象
• C：每次先选择对象再写入
```

### 5. 执行顺序

```text
5. 关键步骤的先后顺序是什么？
• A：完成核心任务后直接结束
• B：完成核心任务后提示结果
• C：完成核心任务后继续打开目标、跳转页面或执行下一步
```

### 6. 外部依赖接受范围

```text
6. 如果纯快捷指令不稳定，是否接受替代路径？
• A：只接受纯快捷指令
• B：接受快捷指令 + URL Scheme / 第三方动作
• C：接受快捷指令 + Minis / 外部服务的混合方案
```

## 推荐流程写法

推荐流程只保留关键阶段，不写展开解释。

推荐：

```text
推荐流程：手动运行 → 获取输入 → 写入目标 → 提示完成
```

不推荐：

```text
推荐流程：我们先弹出输入框，然后根据你的选择可能会……
```

## 可复制确认文本写法

推荐：

```text
可直接复制确认：按推荐流程：1A、2A、3B、4B、5B。
```

如果存在默认值：

```text
可直接复制确认：按推荐流程：1A、2A、3B、4B、5B；默认目标按当前配置执行。
```

## 典型触发场景

- “帮我做个快捷指令”但没有说明输入和输出
- 同一句需求可能对应多种动作链
- 目标应用明确，但写入方式不明确
- 目标明确，但执行顺序不明确
- 完成后是否继续打开 App 或跳转页面不明确

## 免澄清条件

满足以下条件时可直接构建：

- 目标明确
- 输入明确
- 输出明确
- 顺序明确
- 是否接受外部依赖明确

缺失信息若只影响默认值、不影响路线，可先声明默认假设后继续。
