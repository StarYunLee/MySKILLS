# KNOWN_PITFALLS

## 作用

按动作标识符索引已知陷阱。生成 XML 前先查此表，避免重复踩坑。每个条目记录：陷阱描述、正确写法、错误写法、来源。

---

## 通用陷阱

### P-GEN-01: 显示参数必须用 TokenString

**影响动作**：Notification, Show Result, Alert, Show Alert

**陷阱**：显示参数（用户可见文本）即使只引用单个变量，也必须用 `WFTextTokenString`。用 `WFTextTokenAttachment` 会导致运行时字段显示为空/默认文本。

**正确**：
```xml
<key>Text</key>
<dict>
    <key>Value</key>
    <dict>
        <key>string</key>
        <string>￼</string>
        <key>attachmentsByRange</key>
        <dict>
            <key>{0, 1}</key>
            <dict>
                <key>OutputUUID</key><string>UUID-HERE</string>
                <key>OutputName</key><string>Text</string>
                <key>Type</key><string>ActionOutput</string>
            </dict>
        </dict>
    </dict>
    <key>WFSerializationType</key>
    <string>WFTextTokenString</string>
</dict>
```

**错误**：用 `WFTextTokenAttachment` 包裹变量引用。

**来源**：127-shortcut corpus 验证 + 运行时测试

---

### P-GEN-02: If 条件必须显式设置 WFInput

**影响动作**：`is.workflow.actions.conditional`

**陷阱**：所有条件码（包括数字码 0-3）都必须显式设置 `WFInput` 为 Variable wrapper。没有"隐式输入"模式——旧文档说数字码用隐式输入是错误的。

**正确**：
```xml
<key>WFInput</key>
<dict>
    <key>Type</key><string>Variable</string>
    <key>Variable</key>
    <dict>
        <key>Value</key>
        <dict>
            <key>OutputUUID</key><string>UUID-HERE</string>
            <key>OutputName</key><string>Text</string>
            <key>Type</key><string>ActionOutput</string>
        </dict>
        <key>WFSerializationType</key>
        <string>WFTextTokenAttachment</string>
    </dict>
</dict>
```

**错误**：省略 WFInput 或用 `WFTextTokenString` 包裹。

**来源**：Apple 官方 sample shortcut 验证

---

### P-GEN-03: 占位符位置不能手算

**陷阱**：`attachmentsByRange` 的 `{position, 1}` 必须精确指向 `￼` 字符的位置。手动数字符位置极易出错，尤其是含 emoji 或多字节字符时。

**正确做法**：使用 `scripts/placeholder-range` 计算。

**来源**：多次实战踩坑

---

### P-GEN-04: 重复 UUID

**陷阱**：使用 `11111111-1111-1111-1111-111111111111` 这类重复模式的 UUID。验证器会拒绝这类 UUID。

**正确做法**：`python3 -c "import uuid; print(str(uuid.uuid4()).upper())"`

---

### P-GEN-05: Comment 中不能出现 WF 键名或 UUID

**陷阱**：在 Comment 文本中写 `WFInput`、`OutputUUID` 等 plist 技术术语。

**正确**：`- Input uses the formatted date from Format Date above`
**错误**：`- WFInput references UUID A1B2C3D4...`

**来源**：验证器规则

---

### P-GEN-06: 第二个 Comment 必须含固定文字

**陷阱**：第二个 Comment 动作缺少 `Shortcuts generated by Shortcuts Playground.`。

**来源**：验证器规则

## Replace Text 陷阱

### P-REPLACE-01: WFInput 引用 ActionOutput 必须用 TokenString

**影响**：`is.workflow.actions.text.replace`

**陷阱**：Replace Text 的 `WFInput` 引用 ActionOutput 时，必须用 `WFTextTokenString`（带 `￼` 占位符），不能用裸 `WFTextTokenAttachment`，也不能用 `Type=Variable` 包装 ActionOutput。

**例外**：引用 Named Variable 时可以用 Variable wrapper。

**来源**：CleanText 案例实战（2026-05-28）

---

### P-REPLACE-02: WFReplaceTextReplace 纯常量不用 TokenString

**陷阱**：替换值是纯常量时用了 `WFTextTokenString` 包装。验证器的 `iter_empty_strings` 会对 `WFTextTokenString` 内的 `string` key 做 `.strip()`，导致纯空格替换值被判为空。

**正确**：纯常量替换值用 plain `<string>`。

**来源**：CleanText 案例实战（2026-05-28）

---

### P-REPLACE-03: 富文本输入做替换无效

**陷阱**：从剪贴板或分享输入获取的内容可能是富文本对象，直接对富文本做 Replace Text 正则替换可能无效。

**正确做法**：在 Replace Text 之前插入 Text 动作（`gettext`），用 TokenString 引用输入变量，强制 coerce 为纯文本字符串。

**错误做法**：用 `getmarkdownfromrichtext`（会残留 Markdown 标记）。

**来源**：CleanText 案例实战（2026-05-28）

---

## Find Notes 陷阱

### P-NOTES-01: 按标题查找必须用 Operator 99

**影响**：`is.workflow.actions.filter.notes`

**陷阱**：按标题查找笔记时，用 `Operator = 4`（equals）而不是 `Operator = 99`（contains）。Operator 4 在某些情况下匹配不到预期笔记。

**正确**：`Property = Name`, `Operator = 99`

**来源**：XML Snippet Patterns + 实战验证

---

### P-NOTES-02: Append to Note 的 WFNote 不是标题字符串

**影响**：`is.workflow.actions.appendnote`

**陷阱**：把 `WFNote` 设为笔记标题的字符串。`WFNote` 必须是 Note 对象引用（来自 Find Notes 的输出），不是标题字符串。

**来源**：XML Snippet Patterns

---

## Weather 陷阱

### P-WEATHER-01: Weather Detail 不能走 Named Variable

**影响**：`is.workflow.actions.properties.weather.conditions`

**陷阱**：把天气输出先存到 Named Variable，再传给 Get Detail of Weather Conditions。这会导致属性名降级为通用 "Detail"。

**正确做法**：直接引用 Get Current Weather / Get Weather Forecast 的 ActionOutput。

**来源**：BEST_PRACTICES

---

### P-WEATHER-02: Sunrise/Sunset 是列表

**陷阱**：从 Daily forecast 获取的 `Sunrise Time` 和 `Sunset Time` 是列表，不能直接传给 Format Date。

**正确做法**：先加 Get Item from List（Sunrise 取 First Item，Sunset 取 Last Item）。

**来源**：BEST_PRACTICES

---

### P-WEATHER-03: WFContentItemPropertyName 不能留 "Detail"

**陷阱**：`WFContentItemPropertyName` 留了占位值 `Detail` 而不是实际属性名。

**正确值**：`Temperature`, `Humidity`, `Condition`, `Sunrise Time` 等（见 ACTION_PARAM_INDEX #12 完整列表在 BEST_PRACTICES）。

---

## Date 陷阱

### P-DATE-01: Get Time Between Dates 不能用 CurrentDate 魔法令牌

**影响**：`is.workflow.actions.gettimebetweendates`

**陷阱**：直接在 `WFTimeUntilFromDate` 中使用 `CurrentDate` magic token。导入后显示为空/默认日期。

**正确做法**：先插入 Date 动作设为 Current Date，再引用该 Date 动作的输出。

**来源**：BEST_PRACTICES

---

### P-DATE-02: 日期参数必须用 TokenString

**影响**：`is.workflow.actions.gettimebetweendates`

**陷阱**：日期参数用裸 `WFTextTokenAttachment`。结构上验证通过，但导入后显示为 "First Date" / "Second Date" 占位。

**正确做法**：`WFInput` 和日期操作数都用 `WFTextTokenString`。

---

## Health 陷阱

### P-HEALTH-01: 不要设 WFHealthQuantityType

**影响**：`is.workflow.actions.filter.health.quantity`

**陷阱**：设置顶层 `WFHealthQuantityType`。当前 iOS Shortcuts 忽略这个过时键，导致渲染为通用 Health Samples。

**正确做法**：把样本类型放在 `WFContentItemFilter` 的 Type predicate row 中（Operator 4, Bounded true, Removable false）。

---

### P-HEALTH-02: 使用 Find Health Samples picker label

**陷阱**：用 SDK 名称（如 `Sleep Analysis`, `Active Energy Burned`）而不是 picker label。

**正确 label**：`Sleep`（不是 Sleep Analysis）、`Exercise Minutes`（不是 Exercise Time）、`Active Calories`（不是 Active Energy）。

---

### P-HEALTH-03: Sleep Duration 是秒数

**陷阱**：Sleep Duration 除以 60 当作"小时"。实际上 Math coerce 后是秒数。

**正确**：除以 3600 得小时，除以 60 得分钟。

---

## Calendar 陷阱

### P-CAL-01: Find Calendar Events 日期过滤不能用 Operator 3

**影响**：`is.workflow.actions.filter.calendarevents`

**陷阱**：使用 `Operator: 3` 过滤未来事件。导入后显示为红色无效条件。

**正确**：用 `Operator: 1002`（is today）+ `Operator: 2`（is after Current Date）。

---

## API / HTTP 陷阱

### P-API-01: JSON 布尔值被 coerce 为数字

**陷阱**：JSON 响应中的 `true`/`false` 在 Shortcuts 中被转为 `1`/`0`。用 `Contains "true"` 字符串检查会失败。

**正确**：用数字条件（`Is Greater Than 0` 或 `Equals 1`）。

---

### P-API-02: JSON null 被 coerce 为空

**陷阱**：比较 JSON null 时用字符串 `"null"`。

**正确**：用 If Has Any Value（code 100）/ Does Not Have Any Value（code 101）。

---

### P-API-03: WFJSONValues 嵌套对象渲染异常

**陷阱**：复杂嵌套 JSON 用 `WFJSONValues` 导致 Number 0、空行或数据丢失。

**正确**：改用 JSON Text 动作 + `WFRequestVariable` + Body Type = File + Content-Type: application/json。

---

### P-API-04: 孤儿 JSON Text 动作

**陷阱**：创建了 JSON Text 动作但没有被任何 `WFRequestVariable` 引用。

**正确**：每个 JSON Text 都必须是某个请求的 `WFRequestVariable`，或者直接删除。

---

## Location 陷阱

### P-LOC-01: 位置参数不能用 TokenString

**影响**：`WFLocation`, `WFWeatherCustomLocation`, `WFWeatherLocation`

**陷阱**：位置参数用 `WFTextTokenString`。

**正确**：用 `WFTextTokenAttachment` 直接引用 Get Current Location / Location 的输出。
