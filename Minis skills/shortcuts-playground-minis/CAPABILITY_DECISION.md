# CAPABILITY_DECISION.md

## 核心问题

不是每个自然语言自动化需求都适合做成 Apple Shortcuts。

在开始生成前，先回答：

1. **适不适合用 Shortcuts 做主承载？**
2. **是纯 Shortcuts，还是 Hybrid？**
3. **是否值得生成成品，而不是只给执行方案？**

## 决策树

### A. 纯 Shortcuts 优先

满足越多越适合：

- 输入简单：文本、URL、日期、位置、分享输入
- 输出简单：显示、通知、提醒事项、备忘录、文件、分享、打开 URL
- 流程短
- 主要依赖系统原生动作
- 不强依赖网页登录态、Cookie、复杂 DOM
- 失败重试成本低

### B. Hybrid 优先

满足任一项就应重点考虑：

- 需要 Minis 或外部脚本处理复杂逻辑
- 需要下载器、转码器、浏览器自动化、签名器
- 需要调用第三方服务
- 需要在快捷指令中仅承担入口、参数收集、结果回显

### C. 不建议做成快捷指令

满足越多越不适合：

- 强依赖长时间后台运行
- 强依赖复杂网页抓取、登录态、Cookie
- 需要大量文件处理或高失败率重试
- 主要价值其实在 shell / Python / 浏览器自动化，而不是快捷指令交互

## 典型判断

- 查天气：纯 Shortcuts 优先
- 定闹钟：纯 Shortcuts 优先
- 截图后分享：纯 Shortcuts 优先
- 文本快速记入系统应用：纯 Shortcuts 优先
- 第三方笔记应用写入：视 URI、插件或动作能力，可能是纯 Shortcuts，也可能是 Hybrid
- 下载网页资源：视情况，可能 Hybrid
- 下载短视频平台视频：大多应先判断为 Hybrid 或不建议纯 Shortcuts

## 输出要求

在内部规划时，必须给任务打一个标签：

- `shortcut-native`
- `shortcut-hybrid`
- `not-shortcut-first`

这个标签决定后续工作流，而不是等写到一半再临时改路线。
